📋 Project Overview

What is Hatake Hishab?

Hatake Hishab is a comprehensive multi-user farm management application built with modern web technologies.


It allows farmers to:

  • ✓ Track sales, expenses, harvests, and labor
  • ✓ Manage multiple farms with different team members
  • ✓ Use role-based access control (Admin, Accountant, Viewer)
  • ✓ Work in English, Bangla, or Japanese
  • ✓ Add multiple items in one form submission
  • ✓ Generate reports and export data to CSV
  • ✓ Store and manage receipts securely

Multi-Tenant Architecture

The app supports multiple independent farms, each with their own data:

Farm A: Members (admin, accountant, viewer) → Transactions → Crop Batches → Inventory
Farm B: Members → Transactions → Crop Batches → Inventory (completely isolated from Farm A)
Farm C: Members → Transactions → Crop Batches → Inventory

Isolation Mechanism: Row Level Security (RLS) policies at database level ensure users can only access their farm's data.

🗄️ Database Schema

Core Tables

1. profiles (User Profiles)

Field Type Purpose
id UUID Primary Key (from auth.users)
display_name TEXT User's display name
created_at TIMESTAMPTZ Account creation time

2. farms (Multi-tenant Farms)

Field Type Purpose
id UUID Primary Key
name TEXT Farm name
owner_id UUID Farm owner (references profiles)
created_at TIMESTAMPTZ Farm creation time

3. transactions (Main Data Table) ⭐ Most Important

Field Type Purpose
id UUID Primary Key
farm_id UUID Which farm (Multi-tenant key)
kind TEXT Type: 'sale', 'expense', 'harvest', 'labor'
occurred_on DATE When it happened
crop TEXT Crop name or expense category
amount NUMERIC Price in ¥ (Yen)
quantity NUMERIC Volume (kg, pcs, hours)
unit TEXT Unit: kg, pcs, hours
note TEXT Details/comments
created_by UUID Who created it
created_at TIMESTAMPTZ When created

4. farm_members (Membership & Roles)

Field Type Purpose
farm_id UUID Which farm
user_id UUID Which user
role ENUM admin, accountant, field_member, viewer
investment NUMERIC Investment amount
profit_share NUMERIC Profit share % (0-100)
📌 Other Tables:
  • crop_batches: Track crop planting and growth stages
  • inventory_items: Stock tracking and inventory management
  • orders: Customer orders and order status
  • cash_handovers: Track cash given from one person to another
  • receipts: Store uploaded receipts/documents
  • password_resets: Audit log for security

Key Database Concepts

Row Level Security (RLS)

All tables have RLS enabled with this policy:

CREATE POLICY "farm members access transactions"
  ON transactions
  FOR ALL
  USING (is_farm_member(farm_id))
  WITH CHECK (is_farm_member(farm_id));

What this means:

  • ✓ Users can only see transactions for farms they're members of
  • ✓ Viewers can read but RLS blocks their writes
  • ✓ Data is isolated at database level (not just application level)

Example: Adding Multi-Category Expenses

Scenario: User wants to add multiple expenses with different categories in one form submission

Step 1: Code Changes

// Add type definition
type ExpenseLine = {
  id: number;
  category: string;
  amount: string;
  quantity: string;
  unit: string;
};

// Add state
const [expenseLines, setExpenseLines] = useState<ExpenseLine[]>([
  { id: 1, category: "", amount: "", quantity: "", unit: "" }
]);

// Add helpers
const addExpenseLine = () => setExpenseLines(prev => [...prev, blank()]);
const removeExpenseLine = (id) => setExpenseLines(prev =>
  prev.length > 1 ? prev.filter(l => l.id !== id) : prev
);
const changeExpenseLine = (id, patch) => setExpenseLines(prev =>
  prev.map(l => l.id === id ? { ...l, ...patch } : l)
);

Step 2: Update Form UI

// Render multi-line form
expenseLines.map((line, i) => (
  <div key={line.id}>
    <select value={line.category} onChange={...}>
      {/* category options */}
    </select>
    <input type="number" value={line.amount} onChange={...} />
    {expenseLines.length > 1 && (
      <button onClick={() => removeExpenseLine(line.id)}>
        Remove
      </button>
    )}
  </div>
))

<button onClick={addExpenseLine}>
  + Add another item
</button>

Step 3: Update Save Logic

// Transform expenseLines to multiple transactions
const records = expenseLines
  .filter(line => line.category && line.amount)
  .map(line => ({
    kind: "expense",
    occurred_on: form.get("date"),
    crop: line.category,  // category stored as crop
    amount: Number(line.amount),
    farm_id: farm.id,
    created_by: user.id
  }));

// Insert all at once
await supabase.from("transactions").insert(records);

Step 4: Commit & Deploy

git add src/app/page.tsx src/app/globals.css
git commit -m "Add multi-category expense entry

- Implement expenseLines state
- Create multi-line form UI
- Update save logic"

Forgot Password Flow

Note: Passwords reset locally without email (farm is small team)

  1. User clicks "Forgot password" on sign-in
  2. Enters email address
  3. Enters new password they want
  4. Backend checks if account exists in farm
  5. If yes: Sets password directly, signs them in immediately
  6. Records in password_resets table (audit trail)
  7. No email sent (security trade-off for small team)
⚠️ Security Note: Email address alone can reset password. This is acceptable for trusted small teams. For larger farms, configure SMTP and use emailed reset links.
