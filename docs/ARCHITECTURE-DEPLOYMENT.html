Cloud-agnostic deployment guide

Hatake Hishab
Architecture & Deployment

A secure multi-user farm-management app built with Next.js and Supabase. Deploy it on Vercel, AWS, Azure, Google Cloud, an internal Node.js platform, or another HTTPS-capable cloud.

1. Architecture

Frontend

Next.js 16 and TypeScript. Can run on Vercel, Docker, or any Node.js host.

Identity

Supabase Auth handles verified email sign-in and sessions.

Data isolation

farm_id plus Row Level Security separates every farm’s data.

3. Set up Supabase

1Create project

Create a project in the region nearest the farm users. Store the database password safely.

2Apply schema

Open SQL Editor, copy and run supabase/schema.sql. It creates profiles, farms, memberships, transactions, crop batches, inventory, orders, receipts, private Storage, and Row Level Security policies.

3Configure Auth

Under Authentication → URL Configuration, set your Site URL and allow these redirects:

http://localhost:3000
https://your-domain.example.com

4Copy browser-safe credentials

Under Project Settings → API, copy the Project URL and publishable/anon key only.

Never expose the Supabase service-role key. Do not add it to browser code, Git, .env.local, or public cloud variables. It bypasses Row Level Security.

4. Configure and deploy

1Set environment variables

cd hatake-hishab-app
cp .env.example .env.local
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=your-publishable-key

2Validate locally

npm install
npm run dev
# Browse http://localhost:3000
npx next build --webpack

3Commit source

git init
git add .
git commit -m "Initial Hatake Hishab app"
# Push to approved GitHub, GitLab, or internal Git

4Deploy on Vercel

  1. Import the Git repository into Vercel.
  2. Select the Next.js framework preset.
  3. Add both NEXT_PUBLIC_SUPABASE_* variables in Vercel Environment Variables.
  4. Deploy and copy the HTTPS URL.
  5. Add that URL to the Supabase Authentication redirect allow-list.

5Deploy on another cloud

For Cloud Run, App Runner, App Service, Kubernetes, or an internal service: build with npm run build, run with npm start, configure the same variables, enable HTTPS, and permit outbound HTTPS to the Supabase project.

5. Verification checklist

Run these checks after the first deployment.
  1. Open the application over HTTPS.
  2. Create and confirm a test user by email.
  3. Sign in and create a test farm through the authenticated dashboard workflow.
  4. Add a second test user as a farm member.
  5. Confirm a member of a different farm cannot access the first farm’s records.
  6. Upload a test receipt below receipts/<farm-id>/....
  7. Verify an unauthenticated session cannot download the receipt.
  8. Review cloud deployment and Supabase Auth logs.
